# Output Modes Guide

## Overview

`notes` 是所有任务的基础产物。无论用户是否指定其他模式，都先产出 `notes`；其他模式用于补充不同视图。当输入规模大于等于 6 个视频、或明显是系列导航场景时，可自动补 `index`。

多视频输入时，不要只按视频数量决定输出篇数。先判断主题复杂度，再确认用户是想要：

1. 一篇综合 `notes`
2. 多篇不同主题的 `notes`

## Selection

| 模式 | 推荐场景 | 自动补充 |
|------|---------|---------|
| `notes` | 所有输入都需要基础知识整理 | 大系列可补 `index` |
| `brief` | 已有 `notes` 后，需要一页速览 | 无 |
| `glossary` | 概念密集、术语多 | 推荐与 `notes` 搭配 |
| `timeline` | 时间演进、事件顺序、论证过程明显 | 推荐与 `notes` 搭配 |
| `compare` | 至少两个视频或两个视角；存在明显比较维度 | 可补 `index` |
| `index` | 系列入口、导航页 | 常与 `notes` 配套 |
| `qa` | 想支持后续搜索、复习、问答 | 推荐与 `notes` 搭配 |
| `cards` | 学习、复习、原子知识整理 | 推荐与 `notes` 搭配 |
| `visual` | 希望看到画布式结构 | 可与 `notes` / `index` 配套 |

## Rendering Rules

- `notes`：基础产物，必须先生成；单视频是一篇完整笔记，多视频可以是一篇综合笔记，也可以是多篇主题笔记。
- `brief`：压缩到一页，保留最重要判断与证据。
- `glossary`：聚焦术语，不重讲整篇内容。
- `timeline`：用顺序组织材料，不按主题树展开。
- `compare`：先列维度，再看共识与分歧，避免泛泛总结；不能替代基础 `notes`。
- `index`：只做导航和总览，不重复写完整内容。
- `qa`：问题要可检索，答案要短，必须可回溯。
- `cards`：每张卡片一个知识点，不做“散文式笔记”。
- `visual`：把结构变成图，不把整篇笔记塞进一个节点。

## Fallback Rules

- 单视频 + `compare`：降级为 `notes`，并推荐 `timeline` / `glossary` / `visual`
- 非系列输入 + `index`：降级为仅交付 `notes`
- 内容过短 + `cards` / `qa`：减少条目数量，但不跳过 `notes`
- 任何降级都要向用户明确说明原因

## Multi-Video Split Rules

- 主题集中、主线单一：优先建议一篇综合 `notes`
- 主题跨度大、支线明显：优先建议多篇主题 `notes`
- 如果两种组织方式都合理，主动询问用户偏好
- 不对文档数量和篇幅设置硬限制

## Recommendation Rules

交付 `notes` 后，按内容特点推荐 1-2 个附加模式：

- 术语多、定义多：推荐 `glossary`
- 因果关系强、论证顺序明确：推荐 `timeline`
- 观点结构复杂、概念关系强：推荐 `visual`
- 多视频存在共识与分歧：推荐 `compare`
- 系列 / 合集需要导航：推荐 `index`
- 适合复习：推荐 `cards`
- 用户可能反复查询：推荐 `qa`

## Delivery Pattern

收尾时固定按下面顺序汇报：

1. 已生成：`notes`
2. 额外生成：其他本次实际产出的模式
3. 推荐继续尝试：1-2 个最合适的附加模式
4. 说明：降级处理、无字幕、跳过项、输出路径

## Citation Rules

所有模式都要引用来源，优先级如下：

1. 明确时间戳
2. 视频期数 / 分P 编号
3. 视频标题 / BV

如果拿不到时间戳，也要至少保留“视频来源级”引用。

## Ethics Rules

- 不模仿原作者风格
- 不把原视频观点包装成无来源原创内容
- 不生成营销式再传播文案
- 如果内容证据不足，明确写“不确定 / 证据不足”
